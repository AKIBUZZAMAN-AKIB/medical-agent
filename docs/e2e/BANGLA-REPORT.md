## ২. যেটা ভেঙে ছিল এবং এখন ঠিক হয়েছে (F-27 — বাস্তবে ধরা পড়েছে)


`/home/user/.local/node24/bin/node` — অর্থাৎ **যে মেশিনে ফাইলটি লেখা হয়েছিল কেবল সেখানেই চলে**।

এখন ইন্টারপ্রেটার `PATH` থেকে এবং এন্ট্রি-পয়েন্ট রিপোজিটরি-রুট থেকে আপেক্ষিকভাবে রিজলভ হয়।

## ৩. যা এখনো প্রমাণ করা যায়নি — এবং কেন (সৎ অবস্থান)

React-এর `/login` ও `/register` পেজ আসল ব্রাউজারে খুলে ফর্মে লেখা, বাটনে ক্লিক, রিডাইরেক্ট দেখা —
এই ধাপটি **এই ওয়ার্কস্পেসে চালানো সম্ভব হয়নি**। কারণ অনুমান নয়, মাপা:

* মেশিনে RAM মাত্র **১.৯৮ GB**, তাও MongoDB + API সার্ভারের সাথে ভাগ করা।
* ক্লায়েন্ট বান্ডল (৯,৭১৭ মডিউল) কম্পাইল করতে গেলেই কার্নেল প্রসেসটি মেরে ফেলে:

```
✓ 9717 modules transformed.
rendering chunks...
Killed

dmesg: Out of memory: Killed process 10296 (MainThread)
       anon-rss:1359316kB ... oom-kill:constraint=CONSTRAINT_NONE,...,global_oom
```

* Vite dev সার্ভারও একইভাবে মরে (dependency pre-bundling ধাপে)।

তাই স্ক্রিনের DOM, সাকসেস ব্যানার, রিডাইরেক্ট — এগুলো **"NOT TESTED"** হিসেবেই লেখা হয়েছে,
"পাস" বলে চালিয়ে দেওয়া হয়নি। স্ক্রিপ্টটি লেখা ও কমিট করা আছে:
`e2e/browser-auth.e2e.mjs` — ৪ GB RAM-এর মেশিনে চালালেই ফল দেবে
(`docs/e2e/README.md`-তে ধাপে ধাপে নির্দেশনা)।

## ৪. F-28 — ভুল পাসওয়ার্ডে `404` ফেরত আসত → **এখন ঠিক করা হয়েছে**

আগে `api/server/middleware/requireLocalAuth.js` ভুল পাসওয়ার্ডে `404 Not Found` দিত।
ব্রাউজারে ব্যবহারকারী ঠিকই "Incorrect password." দেখতেন (কারণ ক্লায়েন্ট `message` রেন্ডার করে),
কিন্তু মনিটরিং/WAF/রিট্রাই লজিক ভাবত **রাউটটাই নেই**।

এখন `401` ফেরত যায়, সাথে বার্তাও থাকে। যাচাই (`e2e/verify-require-local-auth.js`, কোনো npm
ডিপেন্ডেন্সি ছাড়াই): **৬/৬ পাস**, যার মধ্যে একটি রিগ্রেশন-গার্ড — প্রত্যাখ্যাত লগইন কখনো `404` নয়।
ক্লায়েন্টের কোনো লেখা বদলায়নি (`getLoginError` দুটোতেই একই কী ম্যাপ করে)।

## ৫. ব্যবহারকারীর জন্য দুটি জরুরি নোট

1. **সাইনআপ করলেই লগইন হয় না।** সার্ভার ইচ্ছাকৃতভাবে সবসময় একই বার্তা দেয়
   ("Please check your email to verify your email address.") এবং কোনো সেশন কুকি দেয় না —
   অ্যাকাউন্ট-এনিউমারেশন আটকাতে। UI ৩ সেকেন্ড গুনে `/c/new`-তে পাঠায়, কিন্তু সেশন না থাকায়
   অ্যাপ আবার `/login`-এ ফেরত পাঠাবে। ব্যবহারকারীকে জানাতে হবে: **সাইনআপের পর একবার লগইন করতে হবে।**
2. **SMTP কনফিগার করা নেই** (`emailEnabled: false`), তাই "check your email" বার্তাটি কারো কাছে
   পৌঁছাবে না। প্রোডাকশনে দেওয়ার আগে SMTP বসাতে হবে, নয়তো সরাসরি লগইন-পেজে পাঠাতে হবে।

## ৬. যেভাবে পুনরায় চালাবেন

```bash
# API
MONGO_URI=mongodb://127.0.0.1:27017/LibreChat_e2e_auth node api/server/index.js
# ব্রাউজার-লেভেল অথ ফ্লো (এই মেশিনেও চলে)
node e2e/browser-auth-api.e2e.mjs --base=http://127.0.0.1:3080
# লগইন স্ট্যাটাস কোড (ডিপেন্ডেন্সি ছাড়াই)
node e2e/verify-require-local-auth.js
# UI ফ্লো (৪ GB RAM লাগবে, আগে client/dist বানাতে হবে)
cd client && npm run build && cd .. && node e2e/browser-auth.e2e.mjs --base=http://127.0.0.1:3080
```
